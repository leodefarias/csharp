O controller cuida do protocolo HTTP. O serviço concentra regras de negócio, mapeamentos e chamadas ao banco. Data Transfer Objects (DTOs) representam o contrato; entidades representam a persistência.

Criar e configurar o projeto

  1. Criar Loja.Api com o template ASP.NET Core Web API e controllers.
  2. Instalar Microsoft.EntityFrameworkCore.SqlServer.
  3. Instalar Microsoft.EntityFrameworkCore.Tools.
  4. Adicionar a connection string.
  5. Criar e registrar AppDbContext.
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=(localdb)\\MSSQLLocalDB;Database=LojaAula04Db;Trusted_Connection=True;TrustServerCertificate=True"
  }
}

{

    public List<CriarItemPedidoRequest> Itens { get; set; } = [];
}

public sealed class AtualizarPedidoRequest
{
    public string? Cliente { get; set; }
}

public sealed class PedidoResponse
{
    public int Id { get; set; }
    public string Cliente { get; set; } = string.Empty;
    public StatusPedido Status { get; set; }
    public decimal Total { get; set; }
    public List<ItemPedidoResponse> Itens { get; set; } = [];

Requests e responses são classes do contrato HTTP. No PATCH, propriedades anuláveis permitem distinguir campo ausente de valor informado.

Controller e Service

[ApiController]
[Route("api/[controller]")]
public sealed class PedidosController(
    IPedidoService service) : ControllerBase
{
    [HttpGet("{id:int}")]
    public async Task<ActionResult<PedidoResponse>> Obter(
        int id)
    {
        var pedido = await service.ObterAsync(id);
        return pedido is null ? NotFound() : Ok(pedido);
    }
}

public sealed class PedidoService(AppDbContext db)
    : IPedidoService
{
    public async Task<PedidoResponse?> ObterAsync(int id)
    {
        var pedido = await db.Pedidos
            .Include(item => item.Itens)
            .FirstOrDefaultAsync(item =>
                item.Id == id && item.Ativo);

        return pedido is null ? null : Mapear(pedido);
    }
}
Controllers não consultam o AppDbContext. Todas as consultas, persistências, validações e regras ficam no serviço.

Atualização e exclusão lógica no serviço

if (request.Cliente is not null)
{
    pedido.Cliente = request.Cliente;
}

await db.SaveChangesAsync();

pedido.Ativo = false;
await db.SaveChangesAsync();

As consultas normais filtram somente registros ativos. O controller recebe o resultado do serviço e escolhe a resposta HTTP adequada.

Pedido e ItemPedido

public enum StatusPedido
{
    Aberto,
    Fechado,
    Cancelado
}

public sealed class Pedido
{
    public int Id { get; set; }
    public string Cliente { get; set; } = string.Empty;
    public StatusPedido Status { get; set; } =
        StatusPedido.Aberto;
    public decimal Total { get; set; }
    public DateTime CriadoEm { get; set; } =
        DateTime.UtcNow;
    public bool Ativo { get; set; } = true;
    public List<ItemPedido> Itens { get; set; } = [];
}

public sealed class ItemPedido
{
    public int Id { get; set; }
    public int PedidoId { get; set; }
    public string Produto { get; set; } = string.Empty;
    public int Quantidade { get; set; }
    public decimal ValorUnitario { get; set; }
    public Pedido Pedido { get; set; } = null!;
}

Rotas da API

RotaResponsabilidade
POST /api/pedidosCriar um pedido.
GET /api/pedidosListar pedidos ativos.
GET /api/pedidos/{id}Consultar um pedido.
PATCH /api/pedidos/{id}Atualizar parcialmente um pedido.
DELETE /api/pedidos/{id}Desativar um pedido.
POST /api/pedidos/{id}/fecharValidar estado, calcular total e fechar.
POST /api/pedidos/importacaoValidar e criar uma lista em lote.
GET /api/pedidos/resumoAgrupar por status e calcular indicadores.
CRUD usa rotas simples. Sub-rotas são reservadas para operações de negócio que não representam apenas criar, ler, atualizar ou desativar.
